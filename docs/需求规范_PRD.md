## 一、项目概述

### 1.1 项目名称
**GrowthLens 实习生智能成长系统** (GrowthLens Intern)

### 1.2 项目定位
面向实习生群体的一站式职业成长工具，结合大语言模型能力，打造 **「工作记录 → 复盘沉淀 → 目标追踪 → 求职储备」** 完整成长闭环。

### 1.3 核心价值主张
| 价值点 | 说明 |
|--------|------|
| **智能记录** | AI辅助生成日报周报，降低记录门槛，提升工作效率 |
| **成长可视化** | 技能雷达图、成果趋势图，直观展现成长轨迹 |
| **目标闭环** | 从总目标到子任务的完整拆解与进度追踪 |
| **深度复盘** | 基于工作记录的AI智能复盘，发现问题、优化改进 |
| **求职赋能** | 面经题库与AI答题指导，助力求职面试 |

### 1.4 目标用户
| 用户类型 | 特征 | 核心需求 |
|----------|------|----------|
| **普通用户** | 实习学生 | 记录工作、追踪成长、准备求职 |
| **管理员** | 系统运维人员 | 管理用户、配置AI、查看日志 |

## 二、角色定义

### 2.1 角色权限矩阵

| 功能模块 | 普通用户 | 管理员 |
|----------|----------|--------|
| 日报周报管理 | ✅ 管理个人数据 | ✅ 查看所有数据 |
| 成长轨迹追踪 | ✅ 管理个人数据 | ✅ 查看所有数据 |
| 目标任务管理 | ✅ 管理个人数据 | ✅ 查看所有数据 |
| 智能复盘分析 | ✅ 生成/查看个人复盘 | ✅ 查看所有复盘 |
| 面经题库管理 | ✅ 管理个人题库 | ✅ 查看所有题库 |
| 职场智能助手 | ✅ 使用助手功能 | ✅ 查看所有对话 |
| 用户管理 | ❌ 不可访问 | ✅ 增删改查用户 |
| AI系统配置 | ❌ 不可访问 | ✅ 配置API参数 |
| AI调用日志 | ✅ 查看个人日志 | ✅ 查看所有日志 |

### 2.2 角色标识

| 标识 | 角色名 | 说明 |
|------|--------|------|
| `role=0` | 普通用户 | 默认角色，实习学生 |
| `role=1` | 管理员 | 系统管理员，全权限 |

### 2.3 权限原则

- **数据隔离**：普通用户仅可访问和操作自己创建的数据，所有查询必须携带 `user_id` 条件
- **权限验证**：操作前验证数据归属，非本人数据且非管理员身份时拒绝访问
- **登录鉴权**：所有业务接口必须登录，未登录返回 `code=401`，无权限返回 `code=403`

## 五、业务规则

### 5.1 角色权限规则

1. **普通用户** (`role=0`)：
   - 仅可操作自己创建的业务数据
   - 所有查询必须带 `user_id` 条件
   - 操作前验证数据归属

2. **管理员** (`role=1`)：
   - 全量数据管理权限
   - 可查看所有用户数据
   - 可管理AI配置和模板

3. **鉴权规则**：
   - 所有业务接口必须登录鉴权
   - 未登录返回 `code=401`
   - 无权限返回 `code=403`

### 5.2 事务一致性规则

1. **事务边界**：涉及多表写入的操作必须纳入同一事务
2. **典型场景**：
   - 生成复盘：创建复盘记录 + AI调用日志
   - 删除目标：删除目标 + 关联子任务
   - 删除分类：删除分类 + 重置关联题目分类

3. **回滚机制**：异常时全部回滚，保证数据一致性

### 5.3 业务约束规则

**日报约束**：
- 单用户单日仅可提交一份日报（`user_id + report_date` 唯一）
- 草稿状态可编辑删除，已提交状态需先撤回
- 日报日期不能晚于当前日期

**周报约束**：
- 同一用户同一周仅可有一份周报（`user_id + week_year + week_num` 唯一）
- 周报日期范围必须是完整的一周

**复盘约束**：
- 日度复盘日期范围 = 1天
- 周度复盘日期范围 ≤ 7天
- 月度复盘日期范围 ≤ 31天

**目标任务约束**：
- 子任务截止时间不能晚于目标截止时间
- 目标进度自动计算 = 已完成任务数 / 总任务数 × 100
- 超过截止时间未完成的目标/任务自动标记为延期

**用户约束**：
- 用户名唯一，长度3-20字符
- 密码必须BCrypt加密存储
- 邮箱格式合法且唯一
- 新注册用户默认 `role=0`

### 5.4 AI调用规则

1. **统一入口**：所有AI能力必须通过 `AiService` 接口调用
2. **禁止单独封装**：禁止各模块单独封装大模型HTTP请求
3. **日志记录**：所有调用自动记录完整日志（`ai_call_log`）
4. **配置管理**：AI配置存储在 `ai_system_config` 表，动态生效
5. **异常处理**：调用失败统一抛出 `BusinessException`，返回友好提示
6. **重试机制**：失败最多重试2次，间隔3s/6s
7. **调用限制**：普通用户单日调用上限100次

### 5.5 异步处理规则

1. **适用场景**：耗时较长的AI生成任务（复盘生成、目标拆解）
2. **实现方式**：使用 `@Async` 注解，异步方法定义在独立类中
3. **轮询策略**：前端每2秒轮询一次，最大450次（15分钟）
4. **状态流转**：`0-处理中` → `1-成功` / `2-失败`

## 八、编码规范要点

### 8.1 三层架构
- **Controller**：接收请求、参数校验、调用Service、返回结果
- **Service**：封装业务逻辑、事务控制、业务校验
- **Mapper**：数据库CRUD、SQL编写

### 8.2 命名规范
- 类名：大驼峰（`DailyReportController`）
- 方法名：小驼峰，动词开头（`getUserById`）
- 变量名：小驼峰（`reportDate`）
- 表名：小写，下划线分隔（`daily_report`）

### 8.3 安全规范
- SQL参数绑定使用 `#{}`，禁止 `${}` 拼接业务参数
- 密码BCrypt加密存储
- 所有业务查询必须加 `user_id` 条件

### 8.4 异常规范
- 业务异常抛出 `BusinessException`
- 未授权抛出 `UnauthorizedException`
- 全局异常处理器统一处理，返回标准格式

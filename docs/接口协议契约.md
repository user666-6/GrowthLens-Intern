# 接口协议契约文档

## 1. 文档说明

本文档定义了 GrowthLens Intern 项目的所有接口协议，包括接口路径、HTTP方法、入参、出参、权限要求和错误码。

## 2. 统一返回格式

所有接口返回数据统一封装为 `Result<T>` 格式：

| 字段 | 类型 | 说明 |
|------|------|------|
| code | Integer | 响应状态码：200成功，500系统错误，其他为业务错误码 |
| msg | String | 响应消息 |
| data | T | 响应数据，泛型类型 |

### 2.1 成功响应示例

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": { ... }
}
```

### 2.2 失败响应示例

```json
{
  "code": 401,
  "msg": "未登录或登录已过期",
  "data": null
}
```

### 2.3 特殊说明

`AiSystemConfigController` 返回 `ResponseEntity<Map<String, Object>>` 格式，与统一返回格式不同，详见对应章节。

## 3. 权限级别说明

| 权限级别 | 说明 | 适用路径 |
|----------|------|----------|
| Public | 公开接口，无需登录 | `/user/login`, `/user/register`, `/login` |
| Login | 需要登录 | 除公开接口外的所有接口 |
| Admin | 需要管理员权限（role=1） | `/user/manage/**` |

## 4. 错误码汇总

| 错误码 | 说明 | 触发场景 |
|--------|------|----------|
| 200 | 成功 | 所有成功操作 |
| 400 | 参数异常 | 参数格式错误、参数缺失、参数校验失败 |
| 401 | 未授权 | 未登录、登录过期、Cookie中无token |
| 403 | 无权限 | 非管理员访问管理员接口 |
| 500 | 系统错误 | 系统内部异常、数据库操作失败、AI调用超时 |

## 5. 接口详细定义

### 5.1 用户认证模块

#### 5.1.1 用户登录

- **URL**: `/user/login`
- **Method**: POST
- **权限**: Public
- **入参**:

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| username | String | 是 | - | 用户名 |
| password | String | 是 | - | 密码 |

- **出参**: `Result<SysUser>`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 用户ID |
| username | String | 用户名 |
| nickname | String | 昵称 |
| email | String | 邮箱 |
| phone | String | 手机号 |
| avatar | String | 头像URL |
| status | Integer | 状态：0-禁用，1-启用 |
| role | Integer | 角色：0-普通用户，1-管理员 |

- **说明**: 登录成功后会在Cookie中写入HttpOnly的JWT令牌

#### 5.1.2 用户注册

- **Method**: POST
- **权限**: Public

| email | String | 否 | - | 邮箱 |
| phone | String | 否 | - | 手机号 |

- **出参**: `Result<SysUser>`

#### 5.1.3 用户退出登录

- **URL**: `/user/logout`
- **Method**: POST
- **权限**: Login
- **入参**: 无

- **出参**: 无（重定向到登录页）

## 7. 认证机制说明

### 7.1 JWT令牌

- 登录成功后，服务器生成JWT令牌并写入HttpOnly Cookie
- Cookie名称：`token`
- Cookie属性：HttpOnly, Path=/
- 令牌有效期由配置决定

### 7.2 权限验证流程

1. **LoginInterceptor** 拦截所有请求，放行登录相关路径
2. 从Cookie中获取JWT令牌，验证有效性
3. 解析令牌获取用户ID，查询用户信息
4. 将用户信息存入 `LoginUserHolder`（ThreadLocal）
5. **AdminInterceptor** 拦截 `/user/manage/**` 路径，验证用户角色是否为管理员（role=1）

### 7.3 未授权处理

- **页面请求**：重定向到 `/login`
- **API请求**：返回401状态码和错误JSON
